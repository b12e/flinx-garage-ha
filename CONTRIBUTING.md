# Contributing

Thanks for wanting to improve the F-LinX integration. Here is how to make that count.

## Ideas and bugs: open an issue

An issue is the preferred way to contribute, also for things you could build yourself with the help of LLMs (see below on the usage of LLMs). You can create an issue [here](https://github.com/b12e/flinx-garage-ha/issues/new).

## Pull requests

Pull requests are welcome too. To keep them easy to review and release:

- One change per pull request, against `main`.
- Give it a conventional title (`feat: ...`, `fix: ...`).
- If the change breaks existing setups (renamed entities, changed states or modes, removed actions), add a line starting with `Breaking:` to the description. 

## Using an LLM

That is fine. So do I - this integration is developed with one as well and there's nothing wrong with that. I'd argue this integration wouldn't exist without the help of my dear friend Claude.

HOWEVER: if your plan is to tell your LLM model of choice "add X and make a pull request", skip that step and open an issue describing X instead. 

There's little point of us both burning tokens, and it costs me less time to do it myself than reviewing and re-testing a generated pull request (and making sure nothing malicious slips in), so you get the feature sooner.
